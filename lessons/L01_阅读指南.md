## 第一轮 · 原理

### [ ] 第 1 步：讲义 §0–§1　一次调用的全过程（20 分钟）
- **知识点**
  - HTTP POST + JSON
  - chat template：messages 在服务器端被拼成一整段文本
  - tokenize
  - prefill（并行处理输入）/ decode（逐个生成输出）
  - KV cache
  - 输出比输入贵：decode 受显存带宽限制
  - 缓存命中便宜：前缀的 KV cache 可以复用
- **怎么读**：对照你 nanolm 的 `generate()`，服务器的第 5 步就是它。
- **易错点**
  - 以为模型"看到"的是 messages 这个结构。其实它看到的只是一整串 token，角色只是插在里面的特殊标记（L08 会亲眼看到）。
  - 以为输入输出同价。它们差 4 倍；缓存命中和未命中之间差 50 倍。

### [ ] 第 2 步：先运行演示脚本，再读讲义 §2（30 分钟）
```powershell
conda activate finagent
cd D:\claude\best\finagent
python walkthroughs/L01_raw_http.py
```
一边看输出，一边读讲义 §2。脚本的第 1–4 步分别对应请求、响应、流式、无状态。
- **知识点**
  - 四种角色：system / user / assistant / tool
  - 响应里的 `choices[0].message.content`、`finish_reason`、`usage`
  - SSE：一行行的 `data: ...`，最后一行是 `data: [DONE]`
  - API 没有记忆：多轮对话是每次重发全部历史
- **易错点**
  - 直接发 HTTP 时，`thinking` 写在 JSON 顶层；用 SDK 时要写成 `extra_body={"thinking": ...}`。两种写法最终发出去的 JSON 一样，别混用。
  - `choices` 是**列表**，要写 `[0]`。
  - `content` 可能是 `None`（比如 L04 模型只调用工具、不说话），所以代码里写的是 `content or ""`。
  - 多轮对话时，模型上一轮的回答要以 `assistant` 角色放回去，不能只放用户说过的话。

### [ ] 第 3 步：讲义 §3　token 与计费（20 分钟）
- **知识点**
  - BPE：nanolm 是字符级，真实模型按子词切分
  - 中英文换算：英文约 0.3 token / 字符，中文约 0.6
  - 计费三部分：缓存命中的输入、未命中的输入、输出
  - 高峰价与非高峰价（非高峰半价）
- **怎么读**：拿讲义里 22 / 18 那个例子自己手算一遍，确认得到 $0.0000141。
- **易错点**
  - **`completion_tokens` 已经包含 `reasoning_tokens`**，算钱时不能再加一次思考 token。
  - **`prompt_tokens` = 缓存命中 + 未命中**，算钱时用后两者，不能三个一起加。
  - 价格单位是"美元 / **百万** token"，最后要除以 1,000,000。
  - 高峰时段按 **UTC** 算。洛杉矶周日傍晚已经是 UTC 周一，属于高峰。

### [ ] 第 4 步：讲义 §4–§5　finish_reason 与 thinking（20 分钟）
- **知识点**
  - `finish_reason` 的 6 种取值，其中 `insufficient_system_resource`、`aborted` 是 DeepSeek 特有的
  - thinking 的原理和代价
  - `reasoning_effort`：思考的深度档位
- **易错点**
  - **不检查 `length`**：被截断的回答看起来和完整的一样，数字题尤其危险。
  - **忘了 DeepSeek 默认开 thinking**：不写 `thinking: false`，就会莫名其妙变慢、变贵。
  - **thinking 模式下传 temperature**：不报错，但完全无效。这是本课最重要的一个坑。
  - 带工具的多轮对话里，之前各轮的 `reasoning_content` 必须原样传回。L04 才会碰到，先记住。

### [ ] 第 5 步：讲义 §6–§7　流式、错误与重试（20 分钟）
- **知识点**
  - TTFT（首 token 延迟）与总延迟
  - `stream_options.include_usage`
  - 错误码表：哪些该重试，哪些不该
  - 指数退避 + 随机抖动（jitter）
  - SDK 内置的 `max_retries`
- **易错点**
  - 以为流式能降低总延迟。它只降低**感知**上的等待。
  - 流式最后的 chunk 可能**没有 `choices`**，只带 usage。直接写 `chunk.choices[0]` 会报 `IndexError`。
  - 对 400 / 401 / 402 / 422 做重试：白等，还掩盖了真正的问题。
  - 忘了**重试也会扣费**：请求可能已经生成完了，只是回来的路上断了。

### [ ] 第 6 步：讲义 §8　模型选型（5 分钟）
- **知识点**：能力、价格、延迟三者的权衡，要在自己的任务上实测。
- **易错点**：凭感觉选模型。第三轮的实验就是在教你"用数据选"。

## 第二轮 · 代码（从底层往上读）

依赖关系（箭头表示"用到了"）：

```
cli.py ──────────> openai_compat.py ──> base.py
  │                  │   └──> pricing.py ──> base.py
  │                  └──> tracing.py ──> config.py
  └──> config.py
scripts/l01_compare.py ──> 以上全部
```

### [ ] ① [configs/systems/v0.1.yaml](../configs/systems/v0.1.yaml)（3 分钟）
- **知识点**：一个系统版本 = 一个配置文件；YAML 语法。
- **易错点**
  - YAML 用**空格缩进**，混进 Tab 会报错。
  - key 本身**绝不能写进 yaml**：yaml 会提交到 git。这里只写环境变量的名字 `api_key_env`。

### [ ] ② [src/finagent/config.py](../src/finagent/config.py) + [tests/test_config.py](../tests/test_config.py)（15 分钟）
- **知识点**
  - pydantic `BaseModel`
  - `Field(ge=, le=)` 限定取值范围
  - `Literal` 限定可选值
  - `ConfigDict(extra="forbid")`：出现未定义字段就报错
  - `@model_validator(mode="after")`：跨字段检查
  - `yaml.safe_load`、`load_dotenv`
  - `Path(__file__).resolve().parents[2]`：定位项目根目录
- **重点函数**：`_reject_silently_ignored`、`with_overrides`
- **易错点**
  - **`model_copy(update=...)` 不会重新校验**，所以 `with_overrides` 要重新调用 `model_validate`。测试 `test_overrides_are_revalidated` 专门验证了这一点。
  - **`load_dotenv` 默认不覆盖已经存在的环境变量。** 如果你曾在终端里 `$env:DEEPSEEK_API_KEY=...` 设过旧 key，`.env` 里的新 key 会被悄悄忽略。你刚换过 key，要特别注意：换 key 后最好开一个新终端。
  - 用 `yaml.load` 而不是 `safe_load`，会有执行恶意 YAML 的风险。

### [ ] ③ [src/finagent/llm/base.py](../src/finagent/llm/base.py)（10 分钟）
- **知识点**
  - `@dataclass` 和 pydantic 的分工：内部数据用 dataclass，更轻、不做校验；外部输入（配置）用 pydantic，要校验
  - `Protocol`：结构化类型，不需要继承，方法签名对得上就算实现了接口
  - 类型别名 `DeltaCallback`
- **易错点**
  - `Protocol` 默认**不在运行时检查**。没实现 `chat()` 的类，要到调用时才报错。
  - dataclass 字段的默认值不能直接写 `[]`、`{}` 这类可变对象，要用 `field(default_factory=...)`。这里全是 int 所以没问题，以后加列表字段时会遇到。

### [ ] ④ [src/finagent/llm/pricing.py](../src/finagent/llm/pricing.py) + [tests/test_pricing.py](../tests/test_pricing.py)（10 分钟）
- **知识点**
  - 计费公式的代码实现
  - 带时区（aware）与不带时区（naive）的 datetime
  - `astimezone` 做时区换算
  - 左闭右开区间
  - `pytest.mark.parametrize` 一次测多个用例
  - `pytest.approx` 比较浮点数
- **易错点**
  - **naive datetime** 是时区 bug 的头号来源，所以 `is_peak` 直接拒绝它。
  - 边界：04:00 整**不算**高峰（左闭右开），测试里专门覆盖了。
  - 浮点数用 `==` 比较会因为精度误差失败，要用 `pytest.approx`。
  - Windows 上用 `zoneinfo` 需要额外安装 `tzdata`，所以测试里改用固定的时区偏移。

### [ ] ⑤ [src/finagent/tracing.py](../src/finagent/tracing.py)（5 分钟）
- **知识点**
  - JSONL：只追加、不改写，崩溃也不会损坏之前的记录
  - `threading.Lock`
  - `ensure_ascii=False`：中文原样保存，文件里直接可读
- **易错点**
  - **Windows 上 `open()` 默认编码是 GBK**，不写 `encoding="utf-8"` 就会乱码或报错。本项目所有读写文件的地方都写了。
  - 多线程同时写同一个文件时不加锁，两行内容可能交错在一起。

### [ ] ⑥ [src/finagent/llm/openai_compat.py](../src/finagent/llm/openai_compat.py) + [tests/test_usage.py](../tests/test_usage.py) ★（20 分钟，最重要）
按这个顺序读函数：
1. `__init__`
2. `_build_request`
3. `_call_once`
4. `_call_stream`
5. `parse_usage`
6. `chat`（把前面几个串起来）
7. `_log`

- **知识点**
  - `OpenAI(base_url, timeout, max_retries)`
  - `extra_body`：透传 SDK 不认识的参数
  - `stream=True` 返回一个可迭代对象
  - `getattr(obj, "字段", None)`：取厂商的扩展字段
  - `time.perf_counter`：测耗时用的单调时钟
  - `try / except / raise`：先记录错误，再原样抛出
- **易错点**
  - 直接写 `msg.reasoning_content`：SDK 的类型里没有这个字段，换成 vLLM 这类后端会 `AttributeError`，所以用 `getattr`。
  - 流式时 `chunk.choices` 可能为空，要先 `continue` 跳过。
  - TTFT 以**第一个 token** 为准，思考 token 也算，不是正文的第一个字。
  - `except` 里记录完错误，要用**不带参数的 `raise`** 原样抛出，别吞掉异常。
  - 计价用**请求时写的**模型名，不用响应里的 `model` 字段。

### [ ] ⑦ [src/finagent/cli.py](../src/finagent/cli.py)（10 分钟）
- **知识点**
  - typer：函数参数就是命令行参数，`Annotated[..., typer.Option(...)]` 定义选项
  - `--thinking/--no-thinking` 开关对，默认 `None` 表示"不覆盖配置文件里的值"
  - `typer.Exit(code)` 设置退出码
  - `raise ... from None`
  - rich 画表格，能正确计算中文的显示宽度
- **重点函数**：`_StreamPrinter`、`_explain_error`
- **易错点**
  - **`isinstance` 判断异常时，子类必须写在父类前面**：`AuthenticationError` 在 `APIStatusError` 前面，`APITimeoutError` 在 `APIConnectionError` 前面。写反了，子类那个分支永远进不去。
  - 改了 `pyproject.toml` 的 `[project.scripts]` 后，要重新 `pip install -e .`，`finagent` 命令才会更新。

### [ ] ⑧ [scripts/l01_compare.py](../scripts/l01_compare.py)（10 分钟）
- **知识点**
  - 花钱之前先估算，并要求确认
  - `ThreadPoolExecutor`：网络等待为主的任务用线程池并发
  - `functools.partial`
  - markdown 表格的转义
- **易错点**
  - **闭包延迟绑定**：在循环里写 `lambda q: ask_one(client, v, q)`，lambda 记住的是变量名而不是当时的值。如果它在下一轮循环之后才执行，拿到的就是新值。所以改用 `partial`。
  - 并发数（`--workers`）开太大，容易触发 429。
  - 回答里的 `|` 和换行不处理，会把 markdown 表格弄坏。

## 第三轮 · 动手、实验、作业

### [ ] 运行命令（讲义 §10）
- **每次都先 `conda activate finagent`。** 在 base 环境里运行会找不到 `finagent` 命令，或者报 `ModuleNotFoundError: No module named 'finagent'`。
  - **激活成功的标志是提示符前面出现 `(finagent)`。** 没出现就是没激活，哪怕命令没报错。
  - 不放心就运行 `python -c "import sys; print(sys.executable)"`，应该输出 `...\envs\finagent\python.exe`。
  - 如果 `conda activate` 没反应、也不报错：PowerShell 还没做 conda 初始化，`conda` 实际调用的是 `conda.bat`，激活只发生在一个用完就退出的 cmd 子进程里。运行一次 `conda init powershell`，然后重开终端即可。
- `pytest` 要在项目根目录运行，它从 `pyproject.toml` 读取测试目录。
- PowerShell 里问题用**双引号**包起来。像 `NVIDIA's` 这种带单引号的英文，放进单引号里会断开。
- 故意触发截断：`--max-tokens 5`，看回答末尾的黄色警告。

### [ ] 跑实验（讲义 §11）
- 运行后会先显示估算费用，要输入 `y` 才开始。
- 结果在 `runs/` 目录下，这个目录**不进 git**。结论要写进 `SCOREBOARD.md`，否则换台电脑就丢了。
- 按讲义里的 6 个问题逐条对照着看，不要只看"对了几道"。

### [ ] 查 10-K 填答案（作业 1，最容易出错的一项）
- **财年不等于日历年**
  - NVIDIA 的财年到每年 1 月底结束：FY2025 ≈ 2024 年 2 月到 2025 年 1 月
  - Microsoft 的财年到 6 月 30 日结束
  - Apple 的财年到 9 月底结束
  - Amazon、Meta、Tesla、Alphabet 的财年就是日历年
- **单位**：报表通常是 "in millions"。填的时候写明单位，130,497（百万）和 130.5 billion 是同一个数。
- **口径**
  - Tesla 要取 **Total** automotive revenues，不是其中 "Automotive sales" 那一行。
  - NVIDIA 的 Data Center 是"市场平台"口径的收入，不要和 "Compute & Networking" 这个报告分部混淆。
  - capex 以现金流量表里 "Purchases of property and equipment" 这一行为准。有的公司另外会报一个包含融资租赁的口径，两者不是一个数。
  - 10-K 里是 GAAP 口径，新闻稿里常见 non-GAAP 口径，别混。
- **计算题**
  - 增长率 = (今年 − 去年) ÷ 去年。
  - 注意"百分比"和"百分点"的区别。
  - 用 net sales（收入），不要用 operating income（营业利润）。

### [ ] 代码练习 `--system`（作业 4）
- system 消息必须放在 messages 的**第一条**。
- 没传 `--system` 时，**不要**塞进一条空的 system 消息。
- 写完先跑一遍 `pytest`，确认没有破坏已有功能。

### [ ] git（作业 5）
- `git add .` 之后先运行 `git status`，确认 **`.env` 不在列表里**，`runs/` 目录也没出现。

## 最容易错的 10 件事（读完之后回来自查）

- [ ] 1. thinking 模式下传 temperature：不报错，也不生效。
- [ ] 2. DeepSeek 默认开 thinking，不写 `thinking: false` 就会变慢变贵。
- [ ] 3. 不检查 `finish_reason=length`，把截断的回答当成完整的。
- [ ] 4. 计费时把 `reasoning_tokens` 或 `prompt_tokens` 重复计算。
- [ ] 5. 以为 API 记得上一轮对话。
- [ ] 6. 对 4xx 错误做重试，或者忘了重试也要扣费。
- [ ] 7. 流式时直接写 `chunk.choices[0]`，没考虑列表为空。
- [ ] 8. `isinstance` 判断异常时把父类写在子类前面。
- [ ] 9. Windows 上读写文件不写 `encoding="utf-8"`；`load_dotenv` 不覆盖终端里已有的旧 key。
- [ ] 10. 查 10-K 时搞错财年、单位或口径。
