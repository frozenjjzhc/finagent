## 作业 1：核实 10-K 答案

### 做法

不凭记忆，也不信模型，而是**逐题回到 10-K 原文**：

```
SEC 提交记录接口（按公司 CIK 查）
  → 按"期末日期"找到对应财年的那份 10-K
  → 下载主文档（HTML）→ 转成纯文本
  → 用正则定位关键词（如 "Total automotive revenues"）
  → 读前后文，确认是哪张表、哪一行、哪一列（哪一年）
```

这就是一次**手工的 RAG**：先检索原文，再从原文里读出答案。L05 要做的，就是把这个过程自动化。

### 遇到的坑

- **SEC 返回 403**：EDGAR 要求请求头里写明"项目名 + 真实联系邮箱"，只写项目名和 GitHub 主页会被拒。你的邮箱已经填进 `.env` 的 `SEC_USER_AGENT`，L05 下载财报时直接用。
- **读 10-K 的坑，这次全都实际碰到了**：
  - NVIDIA 的财年和日历年不同：FY2025 截止到 2025 年 1 月 26 日；
  - 报表单位是 "in millions"；
  - Tesla 要取 "Total automotive revenues" 这一行（= 汽车销售 72,480 + 监管积分 2,763 + 租赁 1,827）；
  - Meta 的 $39.23B 是"购置固定资产 37,256 + 融资租赁本金 1,969"的合计口径，不是现金流量表里的那一行。

### 顺带发现的两件事

1. **q08 是我出的题有歧义**：题目写的是 "purchases of property and equipment **(capital expenditures)**"，括号里那个词把两个口径混在一起了。答 $39.23B 的模型不全是它们的错。评测题必须没有歧义，否则判分本身就有争议，这是 L03 的出题原则之一。
2. **模型"多说的一句"也可能是编的**：flash 在 q09 补充说"部分被 Model 3 / Model Y 交付量增长抵消"。10-K 显示交付量是下降的：2023 年 1,808,581 辆，2024 年约 1,789,000 辆。

每道题的出处（10-K 的 accession 编号、哪张表哪一行）都记在 `evalsets/seed_closed_book.jsonl` 的 `source` 字段里。

## 作业 3：给 `finagent ask` 加 `--system` 选项（重点）

### 第 0 步：先写下"做成什么样才算对"

动手之前，先用几句话把行为定下来。这几句话后面会直接变成测试：

1. 传了 `--system "..."`：messages 的**第一条**是 `{"role": "system", "content": "..."}`，第二条是用户的问题。
2. 没传，或者传的是空白：**不加** system 消息，和原来的行为完全一样。
3. 其他选项（`--model`、`--thinking` 等）照常工作。

### 第 1 步：找到要改的地方

读 `cli.py` 的 `ask` 函数，拼 messages 的只有这一行：

```python
messages = [{"role": "user", "content": question}]
```

**同时发现一个陷阱**：函数开头有一行

```python
system = load_config(config)   # 这里的 system 是整份系统配置
```

如果把新参数也命名为 `system`，这一行就会把你传进来的 system prompt 覆盖掉。程序不会报错，但 `--system` 从此失效。这种 bug 最难查。所以参数名改叫 `system_prompt`。

### 第 2 步：设计，把拼 messages 抽成一个函数

与其在 `ask` 里直接加 if 判断，不如单独写一个函数：

```python
def build_messages(question: str, system_prompt: str | None = None) -> list[Message]:
```

为什么值得多写这几行：
- **好测试**：它是个纯函数（同样的输入永远得到同样的输出，不联网、不读文件），测试只要一行 `assert`。
- **职责单一**：`ask` 负责处理命令行，`build_messages` 负责组装消息。
- **为 L02 铺路**：L02 会把消息组装挪到 `pipeline/answer.py`，还会加上日期、few-shot 示例等。到时候整个函数搬过去就行。

### 第 3 步：先写测试（TDD）

`tests/test_cli.py` 里有 4 个测试，对应第 0 步的规则：

| 测试 | 检查什么 |
|---|---|
| `test_without_system_prompt` | 规则 2：不传就只有一条 user 消息 |
| `test_system_prompt_comes_first` | 规则 1：system 在第一条 |
| `test_blank_system_prompt_is_ignored` | 规则 2 的边界：只有空格的也不加 |
| `test_system_option_reaches_the_model` | 端到端：命令行上的 `--system` 真的传到了模型那里 |

第 4 个测试最值得学，因为它**不联网也能测整条命令**：

```python
class FakeClient:                       # 假的客户端：不调 API，只记下收到了什么
    def chat(self, messages, on_delta=None):
        FakeClient.last_messages = messages
        return LLMResponse(content="42", ...)

monkeypatch.setattr(cli, "OpenAICompatClient", FakeClient)   # 把真客户端换成假的
result = CliRunner().invoke(cli.app, ["ask", "What is 6*7?", "--system", "只回答数字", "--no-stream"])
assert FakeClient.last_messages == [{"role": "system", ...}, {"role": "user", ...}]
```

- `CliRunner`：typer 自带的工具，在测试里模拟"在终端敲命令"。
- `monkeypatch.setattr`：测试期间临时替换一个对象，测试结束自动还原。
- **在哪里用，就在哪里替换**：`cli.py` 开头写了 `from finagent.llm.openai_compat import OpenAICompatClient`，import 的那一刻，`cli` 模块就有了自己的 `OpenAICompatClient` 这个名字。所以要替换 `cli.OpenAICompatClient`。如果去替换 `openai_compat.OpenAICompatClient`，`cli` 手里拿着的还是原来那个，替换无效。

写完**先运行一次，看它失败**：

```
ImportError: cannot import name 'build_messages' from 'finagent.cli'
```

失败是好事：说明测试确实在检查新功能。如果还没写实现测试就通过了，那这个测试是无效的。

### 第 4 步：写实现

一共改 3 处。

**① 新函数**（放在 `ask` 上面）：

```python
def build_messages(question: str, system_prompt: str | None = None) -> list[Message]:
    messages: list[Message] = []
    if system_prompt and system_prompt.strip():   # None、""、"   " 都不加
        messages.append({"role": "system", "content": system_prompt.strip()})
    messages.append({"role": "user", "content": question})
    return messages
```

- `system_prompt and system_prompt.strip()`：先排除 `None`，再排除只有空白的字符串。顺序不能反：对 `None` 调用 `.strip()` 会报错，而 `and` 在左边为假时不会执行右边。
- 先放 system，再放 user：顺序就是规则 1。

**② 新参数**（加在 `ask` 的参数列表里）：

```python
system_prompt: Annotated[
    str | None, typer.Option("--system", help="作为 system 消息放在最前面的一段话")
] = None,
```

- 默认值 `None` 表示"没传"。
- **必须显式写 `"--system"`**：typer 默认会把参数名 `system_prompt` 转成 `--system-prompt`。想要更短的 `--system`，就得自己指定。

**③ 替换原来那一行**：

```python
messages = build_messages(question, system_prompt)
```

python -m ruff check src tests scripts walkthroughs
python -m ruff format src tests scripts walkthroughs

**一定要跑全部测试**，不只是新写的那几个：改动可能不小心弄坏了别的功能。

### 第 6 步：用真实 API 试一下

| 命令 | 结果 |
|---|---|
| `finagent ask "What was NVIDIA's total revenue for fiscal year 2025?" --system "Answer with only the number and unit, no explanation."` | `$130.5 billion`。输出从 32 个 token 降到 5 个 |
| `finagent ask "What was Microsoft's total revenue for fiscal year 2025 (ended June 30, 2025)?" --model deepseek-v4-pro` | "Microsoft has not yet reported its fiscal year 2025 results…"（又一次误以为现在是 2025 年） |
| 同上，加 `--system "Today's date is 2026-09-26."` | **"$281.7 billion"**，答对了 |

最后这组对比就是 L02 的核心：**模型不知道的背景信息（比如今天的日期），要由你在 system prompt 里告诉它。** 一句话就把一个"拒答"变成了正确答案。

### 易错点清单

- [ ] 参数名用 `system`，和函数里已有的变量重名，被悄悄覆盖。
- [ ] 忘了显式写 `"--system"`，结果命令行上只能用 `--system-prompt`。
- [ ] system 消息没放在第一条。
- [ ] 没传 `--system` 时仍然塞了一条空的 system 消息。
- [ ] 判断条件写成 `system_prompt.strip()`，传 `None` 时直接报错。
- [ ] 测试里替换错了模块（替换 `openai_compat.OpenAICompatClient` 是无效的）。
- [ ] 测试去调真实 API：又慢又花钱，结果还不稳定。
- [ ] 只跑新测试，不跑全部测试。
