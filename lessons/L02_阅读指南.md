> 配合 [L02_Prompt与结构化输出.md](L02_Prompt与结构化输出.md) 使用。每做完一步就把 `[ ]` 改成 `[x]`。

## 第一轮 · 原理

### [ ] 第 1 步：讲义 §1–§3　system prompt 的结构、什么是好规则（25 分钟）
- **知识点**
  - system prompt 的四块：角色、规则、格式、边界
  - 规则要具体、可执行、可检验
  - 常见反模式
- **怎么读**：打开 `prompts/answer_v2.yaml`，对照讲义 §2 的表，找出每条规则针对的是 L01 的哪个失误。
- **易错点**
  - 以为写一句 "be accurate" 或 "don't hallucinate" 就有用。模型缺的是**具体做法**，不是态度。
  - 只说"不许做什么"，不给出路。要告诉它"不知道时输出 `status: unknown`"。
  - 规则和示例互相矛盾。模型通常跟着示例走。

### [ ] 第 2 步：讲义 §4　few-shot（20 分钟）
- **知识点**
  - 示例以对话轮次的形式放在 system 之后
  - 选示例的 5 条原则：覆盖行为、格式一致、不泄漏、本身合格、分布均衡
- **怎么读**：对比 `answer_v2.yaml` 和 `answer_v3.yaml`，system 部分一字不差，只多了 `examples`。这就是**控制变量**。
- **易错点**
  - **示例里某种行为占多数，模型就偏向它。** v3 的 5 个示例里有 3 个"不回答"，实验里它多拒答了一题。
  - 用评测题或它的答案当示例 = 数据泄漏，分数是假的。
  - 示例回答本身不合格（比如少字段），模型会照着学错。

### [ ] 第 3 步：讲义 §5　先推理后回答（10 分钟）
- **知识点**：模型逐个生成 token，后面能看到前面的内容；生成顺序就是计算顺序；用 JSON 的字段顺序实现 CoT。
- **易错点**
  - 把 `reasoning` 放在 `value` 后面：数值先凭直觉给出，推理只是事后找理由。
  - 分不清"输出里写 reasoning"和 "thinking 模式"：前者便宜、可保存；后者更深、更贵。

### [ ] 第 4 步：先运行演示脚本，再读讲义 §6（30 分钟）
```powershell
python walkthroughs/L02_json_mode.py
```
脚本的第 1–5 步分别对应：`str.format` 的坑、不开 JSON mode、JSON mode 缺少 "json" 一词、合法 JSON ≠ 合格内容、messages 结构与缓存。
- **知识点**
  - 三道防线：prompt 格式说明 → JSON mode → pydantic
  - DeepSeek JSON mode 的三条规矩
  - schema 设计：`Literal`、跨字段校验、`extra="forbid"`、长度限制
  - 带反馈的重试
- **易错点**
  - **以为开了 JSON mode 就万事大吉。** 它只管语法，`{"value": "36 dollars"}` 照样能通过。
  - **prompt 里忘了写 "json"**：DeepSeek 直接返回 400（演示脚本第 3 步亲眼看到）。
  - **没处理空输出**：官方承认偶尔会返回空内容。
  - 重试时只是原样再问一遍，不告诉模型错在哪。

### [ ] 第 5 步：讲义 §7　prompt 是文件（15 分钟）
- **知识点**：版本化、可比较、可测试；`{{变量}}` 模板；日期放最后以保护缓存。
- **易错点**
  - 用 `str.format` 渲染含 JSON 的模板：`KeyError: '"value"'`。
  - 用 `string.Template`：和 `$4.2 billion` 冲突。
  - **把每天都变的内容（日期）放进 system**：前缀一变，后面的示例全都命中不了缓存。

## 第二轮 · 代码

依赖关系（箭头表示"用到了"）：

```
cli.py ──> pipeline/answer.py ──> prompts.py ──> config.py
  │              │                    └──> llm/base.py
  │              ├──> schemas.py
  │              └──> llm/base.py（LLMClient 接口，json_mode 参数）
  └──> llm/openai_compat.py（json_mode → response_format）
```

### [ ] ① 三个 prompt 文件（10 分钟）
[`prompts/answer_v1.yaml`](../prompts/answer_v1.yaml) → [`answer_v2.yaml`](../prompts/answer_v2.yaml) → [`answer_v3.yaml`](../prompts/answer_v3.yaml)
- **怎么读**：像看 git diff 一样，只关注"这一版比上一版多了什么"。
- **易错点**
  - YAML 的多行文本用 `|`（保留换行）或 `|-`（保留换行，去掉结尾换行）。缩进错一格，内容就会出错。
  - 示例的 `assistant` 必须是**一行合法的 JSON**，测试会逐个校验。

### [ ] ② [src/finagent/schemas.py](../src/finagent/schemas.py)（10 分钟）
- **知识点**：`Literal` 类型别名；`Field(max_length=...)`；`@model_validator(mode="after")` 做跨字段检查；`format_value`。
- **易错点**
  - `value` 是 `float`：模型写成 `"130,497"`（带逗号的字符串）会校验失败，而 `"130497"` 会被 pydantic 自动转成数字。要知道 pydantic 默认的"宽松模式"会做这种转换。
  - 跨字段规则写在 `after` 校验器里，这时所有字段都已经各自校验完了。

### [ ] ③ [src/finagent/prompts.py](../src/finagent/prompts.py)（10 分钟）
- **知识点**：正则 `\{\{(\w+)\}\}`；`re.sub` 可以传一个函数做替换；pydantic 模型加载 YAML；messages 的组装顺序。
- **易错点**
  - 在 f-string 里表示字面的花括号要写成 `{{`，所以报错信息里的 `{{{{{key}}}}}` 才会显示成 `{{key}}`。
  - 模板里缺变量要**报错**，而不是悄悄留下 `{{today}}` 发给模型。

### [ ] ④ [src/finagent/pipeline/answer.py](../src/finagent/pipeline/answer.py) ★（15 分钟，最重要）
按顺序读：`parse_answer` → `AnswerResult` → `repair_message` → `answer_question`。
- **知识点**
  - 三种失败分开报告：空输出、不是 JSON、不符合 schema
  - `raise ... from None`：隐藏内部异常链，只给出我们整理过的错误信息
  - `@dataclass` + `@property`：`attempts`、`cost_usd`、`latency_s` 由 `responses` 算出来
  - 重试循环：`for _ in range(max_attempts)`，成功就 `return`
- **易错点**
  - 重试时**忘了把 assistant 的错误输出放回去**，模型就看不到自己错在哪。
  - `messages = [*messages, ...]` 创建的是**新列表**，而不是 `messages.append(...)` 修改原列表。这样测试里记录下来的每一轮 messages 不会被后续修改影响。
  - **花费要把所有尝试加起来**：重试也花钱。只要有一次花费未知（None），总花费就是未知，不能当成 0。

### [ ] ⑤ LLM 层的改动（5 分钟）
[`llm/base.py`](../src/finagent/llm/base.py) 的 `chat()` 多了 `json_mode` 参数；[`llm/openai_compat.py`](../src/finagent/llm/openai_compat.py) 的 `_build_request` 把它变成 `response_format`，调用记录里也多了 `json_mode` 字段。
- **易错点**：给接口（Protocol）加参数时，**所有实现都要跟着改**，包括测试里的假客户端（`FakeClient`、`ScriptedClient`）。L08 的本地模型后端也要实现它。

### [ ] ⑥ [src/finagent/config.py](../src/finagent/config.py) + [configs/systems/v0.2.yaml](../configs/systems/v0.2.yaml)（5 分钟）
- **知识点**：`PromptConfig`；`prompt: None` 表示裸调模式（v0.1）。配置文件里的注释记录了为什么选 v2。
- **易错点**：默认配置从 v0.1 改成了 v0.2。要用旧版本，就得显式写 `--config configs/systems/v0.1.yaml`。

### [ ] ⑦ [src/finagent/cli.py](../src/finagent/cli.py)（10 分钟）
- **知识点**：`ask` 根据配置分成 `_ask_raw` 和 `_ask_structured` 两条路径；`--json` 选项；结构化模式不走流式（JSON 要完整收到才能解析）。
- **易错点**
  - 在结构化模式下用 `--system`：会报错退出（退出码 2），因为 system prompt 已经来自 prompt 文件，两者混用会让实验结果对不上 prompt 版本。
  - 失败时要打印**每一次**的错误原因和最后一次原始输出，方便排查。

### [ ] ⑧ 三个测试文件（15 分钟）
[`tests/test_prompts.py`](../tests/test_prompts.py)、[`tests/test_answer.py`](../tests/test_answer.py)、[`tests/test_cli.py`](../tests/test_cli.py)
- **知识点**
  - `pytest.mark.parametrize` 配合 `pytest.param(..., id=...)`：每个示例一个测试，名字清楚
  - **剧本客户端**（`ScriptedClient`）：按顺序返回预先写好的输出，用来测试重试流程
  - `pytest.fixture`：把"替换客户端"这类准备工作抽出来复用
- **易错点**
  - 测试 prompt 时只测"能加载"，不测**示例是否合格、是否泄漏**。这两项才是真正会坑人的地方。
  - `parametrize` 传生成器已被 pytest 标记为弃用，要传列表。

### [ ] ⑨ [scripts/l02_prompts.py](../scripts/l02_prompts.py)（10 分钟）
- **知识点**
  - 控制变量：模型、thinking、题目、日期都固定，只换 prompt
  - 整个实验用同一个日期（`today`），保证可复现
  - `quick_grade`：百分比按"绝对差 0.5 个百分点"判，金额按"相对误差 1%"判
- **易错点**
  - 把 `quick_grade` 当成正式的评测。它的容差是临时定的，L03 会重新设计。
  - 百分比也用相对误差来判：18.5% 和四舍五入后的 19% 相对误差是 2.7%，会被误判为错。所以百分比改用绝对差。

## 第三轮 · 动手、实验、作业

### [ ] 运行命令（讲义 §10）
- `finagent ask` 默认已经是 v0.2（结构化输出）。
- **连续问两个问题**，观察底部"缓存命中"的变化：第二次会明显变多。

### [ ] 读实验结果（讲义 §9）
- 先看汇总表，再看逐题表，最后看"自评信心 vs 对错"表。
- **不要只看总分**：v1 → v2 的提升具体来自哪几题？分别是哪条规则起的作用？

### [ ] 作业（讲义 §11）
- **作业 1（随机性）**：逐题对比两次运行，不要只比总分。
- **作业 2（示例分布）**：写 v4 时，示例里**不能**出现评测集公司的真实数字；写完先跑 `python -m pytest -q`，测试会自动检查新示例是否合格、是否泄漏。
- **作业 3（thinking）**：同时比较准确率和花费，算一下"多答对一题要多花多少钱"。

## 最容易错的 10 件事（读完之后回来自查）

- [ ] 1. 规则写成空话（"be accurate"），而不是具体做法。
- [ ] 2. 只说"不许编造"，不告诉模型不知道时该输出什么。
- [ ] 3. few-shot 示例的行为分布不均衡，把模型带偏。
- [ ] 4. 示例用了评测题或它的答案（数据泄漏）。
- [ ] 5. 把 `reasoning` 放在 `value` 后面。
- [ ] 6. 以为 JSON mode 保证内容正确；或者 prompt 里忘了写 "json"。
- [ ] 7. 不处理空输出；重试时不把错误反馈给模型。
- [ ] 8. 用 `str.format` 渲染含 JSON 的模板。
- [ ] 9. 把每天都变的日期放进 system prompt，破坏缓存。
- [ ] 10. 在同一批 10 道题上反复改 prompt，直到分数变高（对评测集过拟合）。
