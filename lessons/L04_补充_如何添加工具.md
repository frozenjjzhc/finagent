# L04 补充 · 计算器是怎么加进来的，以及怎么加一个新工具

> 配合 [L04_Tool_Use.md](L04_Tool_Use.md) 使用。
> 配套演示脚本：`python walkthroughs/L04_add_tool.py`（第 1~3 步离线；第 4 步联网，不到 $0.001）。
> 完整示例：本讲义带着你加了第二个工具 `convert_units`（单位换算），代码在 [src/finagent/tools/units.py](../src/finagent/tools/units.py)。

---

## 0. 先看全景：一个函数要经过 8 层，才能被模型调用

```
① 写一个普通的 Python 函数                        tools/calculator.py      calculate()
      │  @tool 装饰器
② 变成一个 Tool 对象（名字、描述、参数模型、函数）   tools/registry.py        tool()
      │  Tool.schema()
③ 生成说明书（JSON Schema）                        tools/registry.py        Tool.schema()
      │  放进总表
④ 注册到 AVAILABLE_TOOLS                           tools/__init__.py
      │  配置里写上名字
⑤ 在系统配置里启用                                  configs/systems/v0.4.yaml  tools.enabled
      │  tool_options → build_registry
⑥ 组装成 ToolRegistry，交给工具循环                 pipeline/answer.py、agent/loop.py
      │  每一轮：schemas() 放进请求；模型请求调用时 execute()
⑦ 在 system prompt 里告诉模型要用它                 prompts/answer_ctx_tools_v1.yaml
      │
⑧ 写测试、跑评测，确认它真的有用                    tests/test_tools.py、finagent eval
```

加一个新工具，你**真正要写的只有 ①（函数）、④（一行注册）、⑤（一行配置）、⑦（prompt 里的一句话）和 ⑧（测试）**。②③⑥ 是框架代码，已经写好，所有工具通用。下面先以计算器为例把每一层讲透，再手把手加一个新工具。

## 1. 以计算器为例，逐层拆解

### 1.1 第 ① 层：写一个普通函数

[tools/calculator.py](../src/finagent/tools/calculator.py) 里有两个函数，分工不同：

```python
def evaluate(expression: str) -> float:
    """真正干活的：用 AST 白名单安全地计算表达式。出错时抛 ToolError。"""
    ...

@tool
def calculate(expression: str) -> str:
    """Evaluate an arithmetic expression exactly and return the numeric result. Use this tool for every calculation (differences, sums, ratios, percentage changes, averages, growth rates) instead of doing arithmetic in your head. Independent calculations can be requested in parallel.

    Args:
        expression: One arithmetic expression using plain numbers, + - * / ** and parentheses, for example "(5829 - 5735) / 5735 * 100". Do not use thousands separators, currency signs, percent signs or variable names.
    """
    return format_number(evaluate(expression))
```

- `evaluate`：普通的 Python 函数，返回 float，可以在别的地方复用（测试里就直接测它）。
- `calculate`：**给模型用的外壳**。它做三件事：
  1. 调用 `evaluate` 干活；
  2. 把结果格式化成字符串（`format_number`：12 位有效数字，避免 `0.30000000000000004`）；
  3. 用 docstring 告诉模型"我是干什么的、什么时候用、参数怎么写"。

**为什么分两层**：干活的逻辑和"给模型看的说明"分开，干活的逻辑可以单独测试、单独复用。工具很简单时，也可以合成一个函数（下面的 `convert_units` 就是一个函数）。

**docstring 为什么是英文**：它会原样发给模型，是 prompt 的一部分。项目里所有给模型看的内容（prompt、工具说明）都用英文，给人看的注释用中文。

### 1.2 第 ② 层：`@tool` 把函数变成 Tool 对象

`@tool` 写在函数定义上面，等价于 `calculate = tool(calculate)`：把函数交给 `tool()` 处理，再把返回值（一个 `Tool` 对象）赋回给同一个名字。所以加了装饰器以后，`calculate` 已经不是函数，而是一个 `Tool`；原来的函数保存在 `calculate.fn` 里。

[tools/registry.py](../src/finagent/tools/registry.py) 的 `tool()` 做了 5 件事。演示脚本第 1 步把每一步的结果都打印了出来（用的是 `convert_units`，参数更多，看得更清楚）：

**(1) `inspect.signature(fn)`：读出参数名和默认值**
```
(value: 'float', from_scale: 'Scale', to_scale: 'Scale') -> 'str'
```
类型还是字符串 `'float'`、`'Scale'`，因为文件开头写了 `from __future__ import annotations`（所有注解都先存成字符串）。

**(2) `get_type_hints(fn)`：把字符串还原成真正的类型**
```
value      <class 'float'>
from_scale typing.Literal['units', 'thousands', 'millions', 'billions']
to_scale   typing.Literal['units', 'thousands', 'millions', 'billions']
```
`'Scale'` 被还原成了 `units.py` 里定义的 `Literal[...]`。这一步如果发现某个参数**没写类型注解**，`tool()` 直接报错：没有类型，就生成不了说明书。

**(3) `_parse_docstring`：拆出工具描述和每个参数的描述**
- `"Args:"` 之前的部分 → 工具的 `description`
- `"Args:"` 之后，每个 `名字: 描述` 开头的行 → 这个参数的 `description`；缩进更深的行是上一行的续行

没有 docstring 也直接报错：模型要靠描述决定什么时候调用它。

**(4) `create_model`：用这些信息动态生成一个 pydantic 模型**
```python
fields[name] = (类型, Field(默认值, description=参数描述))   # 没有默认值时，默认值写 ...（表示必填）
args_model = create_model("convert_units_args", __config__=ConfigDict(extra="forbid"), **fields)
```
这相当于你手写了：
```python
class convert_units_args(BaseModel):
    model_config = ConfigDict(extra="forbid")
    value: float = Field(..., description="The number as written in the source, ...")
    from_scale: Literal["units", "thousands", "millions", "billions"] = Field(..., description="...")
    to_scale: Literal["units", "thousands", "millions", "billions"] = Field(..., description="...")
```
**这个模型一身两用**：生成说明书（第 ③ 层），以及校验模型传来的参数（第 ⑥ 层）。L02 学的 pydantic 在这里又用上了。

**(5) 包成 `Tool(name, description, fn, args_model)` 返回。**

### 1.3 第 ③ 层：生成说明书

`Tool.schema()` 调用 `args_model.model_json_schema()`，去掉 pydantic 自动加的 `title`（对模型没用，还白占 token），再包上 OpenAI 要求的外层格式。`convert_units` 最终发给模型的说明书（演示脚本的真实输出）：

```json
{
  "type": "function",
  "function": {
    "name": "convert_units",
    "description": "Convert a number from one scale to another (units, thousands, millions, billions). Use this when ...",
    "parameters": {
      "additionalProperties": false,
      "properties": {
        "value":      {"description": "The number as written in the source, ...", "type": "number"},
        "from_scale": {"description": "The scale the value is written in.", "enum": ["units", "thousands", "millions", "billions"], "type": "string"},
        "to_scale":   {"description": "The scale the question asks for.",   "enum": ["units", "thousands", "millions", "billions"], "type": "string"}
      },
      "required": ["value", "from_scale", "to_scale"],
      "type": "object"
    }
  }
}
```

对照函数签名看：

| 函数里写的 | 说明书里变成 |
|---|---|
| 函数名 `convert_units` | `"name"` |
| docstring 第一段 | `"description"` |
| `value: float` | `"type": "number"` |
| `from_scale: Literal[...]` | `"type": "string"` + `"enum": [...]`：模型只能从这 4 个值里选 |
| 没有默认值 | 出现在 `"required"` 里 |
| Args 段的描述 | 每个参数的 `"description"` |
| `extra="forbid"` | `"additionalProperties": false` |

### 1.4 第 ④ 层：注册

[tools/__init__.py](../src/finagent/tools/__init__.py)：

```python
from finagent.tools.calculator import calculate
from finagent.tools.units import convert_units

AVAILABLE_TOOLS: dict[str, Tool] = {t.name: t for t in (calculate, convert_units)}
```

`AVAILABLE_TOOLS` 是"工具名 → Tool"的总表。**注册不等于启用**：放进总表，只是说"项目里有这个工具"；哪个系统版本给模型哪些工具，由配置决定（下一层）。

### 1.5 第 ⑤ 层：在配置里启用

[configs/systems/v0.4.yaml](../configs/systems/v0.4.yaml)：

```yaml
tools:
  enabled: [calculate]   # 从 AVAILABLE_TOOLS 里挑哪些发给模型
  max_rounds: 6          # 每次尝试最多几轮工具调用
  json_mode: false       # 工具循环里不开 JSON mode（L04 讲义 §5.4）
```

为什么启用放在配置里（ADR-3）：做消融实验时只改配置、不改代码。比如想试试"计算器 + 单位换算"，复制一份配置，把 `enabled` 改成 `[calculate, convert_units]` 就行，SCOREBOARD 的每一行也就对应一个配置文件。

名字写错（比如 `calculater`）会直接报错，而不是悄悄少一个工具：
```
未知的工具：['calculater']，可用的：['calculate', 'convert_units']
```

### 1.6 第 ⑥ 层：组装、发送、执行

**组装**：[pipeline/answer.py](../src/finagent/pipeline/answer.py) 的 `tool_options` 把配置变成参数：

```python
def tool_options(cfg: ToolsConfig | None) -> dict[str, Any]:
    if cfg is None or not cfg.enabled:
        return {}                                        # 没有工具
    return {
        "tools": build_registry(cfg.enabled),            # 按名字从 AVAILABLE_TOOLS 取出，组成 ToolRegistry
        "max_rounds": cfg.max_rounds,
        "tool_json_mode": cfg.json_mode,
    }
```

评测（`eval/run.py`）和命令行（`cli.py` 的 `ask`）都这样用：`answer_question(..., **tool_options(system.tools))`。

**发送和执行**：[agent/loop.py](../src/finagent/agent/loop.py) 里，注册表只在两个地方出现：

```python
tools = registry.schemas()                                   # 所有启用的工具的说明书
resp = client.chat(messages, json_mode=json_mode, tools=tools)   # → 请求里的 tools 参数
...
for call in resp.tool_calls:
    step = registry.execute(call)                            # 按 call.name 找到对应的 Tool，执行
```

`registry.execute(call)` 按名字找到 Tool，调用 `Tool.run(call.arguments)`。`run` 在执行函数之前先过三关，任何一关失败都**不抛异常**，而是返回一条 `"Error: ..."` 文字回传给模型。演示脚本第 2 步的真实输出：

| 模型传来的参数 | 卡在哪一关 | 返回给模型的文字 |
|---|---|---|
| `{"value": 5829, "from_scale": "thousands", "to_scale": "millions"}` | 全部通过 | `5.829` |
| `value=5829` | ① 不是 JSON | `Error: arguments are not valid JSON (Expecting value).` |
| `[5829, "thousands", "millions"]` | ② 不是对象 | `Error: arguments must be a JSON object.` |
| `{"value": 5829, "from_scale": "thousands"}` | ③ 漏了参数 | `Error: invalid arguments: to_scale: Field required.` |
| `{"value": 1, "from_scale": "thousand", ...}` | ③ 不在 enum 里 | `Error: invalid arguments: from_scale: Input should be 'units', 'thousands', 'millions' or 'billions'.` |
| `{..., "round": 2}` | ③ 多了参数 | `Error: invalid arguments: round: Extra inputs are not permitted.` |
| `{"value": "5829", ...}` | 通过（宽松模式把字符串转成了数字） | `5.829` |
| `{"value": NaN, ...}` | 函数自己检查，抛 ToolError | `Error: value must be a finite number` |

注意倒数第二行：pydantic 默认是**宽松模式**（L02 讲过），字符串 `"5829"` 会被转成数字。对工具参数来说这是好事：模型偶尔会给数字加引号，没必要为此报错。

### 1.7 第 ⑦ 层：告诉模型要用

L04 的实验证明，**只把工具放进 tools 参数，模型不一定会用**：不给说明时，只有 28% 的题用了计算器。所以 [prompts/answer_ctx_tools_v1.yaml](../prompts/answer_ctx_tools_v1.yaml) 在 system prompt 里加了一段：

```
Calculator: you have a "calculate" tool. Use it for every arithmetic step instead of
computing in your head (independent steps can be requested in parallel). Only after you
have all the results, give your final answer.
```

工具的 description 说"它是什么、怎么用"；system prompt 说"在这个任务里，你必须用它"。两者都要有。

### 1.8 第 ⑧ 层：测试和评测

- **测试**（[tests/test_tools.py](../tests/test_tools.py)）：测函数本身（算得对不对、该拒绝的是否拒绝）、测说明书（字段、类型、required）、测 `execute` 的错误回传。全程不联网，一秒跑完。
- **评测**：工具有没有用，只能在评测集上量：准确率、**工具使用率**（报告里的"用了工具的题"）、花费、延迟。计算器的结论是 +5 个百分点（L04 讲义 §7）。

## 2. 动手：加一个新工具 `convert_units`（单位换算）

### 2.1 先问：值不值得做成工具？

不是什么都该做成工具。先回答四个问题：

| 问题 | 单位换算的回答 |
|---|---|
| 模型自己做容易错吗？ | 会。L03、L04 的错误里专门有一类 `scale_error`（差了 1000 倍） |
| 程序做能保证对吗？ | 能，就是乘除 1000 的幂 |
| 输入能用几个明确的参数描述吗？ | 能：一个数、原来的单位、目标单位 |
| 它和已有的工具重复吗？ | **部分重复**：计算器也能 ÷1000。专用工具的好处是逼模型明确写出"原来是千、要换成百万"，不容易弄反 |

最后一条说明，它**可能**有用，但要靠评测来证明（2.8 节）。这也是我们把它当教学示例、但**没有在 v0.4 里启用**的原因。

### 2.2 第 1 步：写函数

新建 [src/finagent/tools/units.py](../src/finagent/tools/units.py)：

```python
from __future__ import annotations

import math
from typing import Literal

from finagent.tools.calculator import format_number          # 复用计算器的数字格式化
from finagent.tools.registry import ToolError, tool

Scale = Literal["units", "thousands", "millions", "billions"]    # ← A
_FACTOR: dict[str, float] = {"units": 1.0, "thousands": 1e3, "millions": 1e6, "billions": 1e9}


@tool                                                           # ← B
def convert_units(value: float, from_scale: Scale, to_scale: Scale) -> str:   # ← C
    """Convert a number from one scale to another (units, thousands, millions, billions). Use this when the excerpt states numbers in one scale (for example a table "in thousands") but the question asks for another (for example "in millions"). Do not use it for percentages.

    Args:
        value: The number as written in the source, for example 5829 for "$5,829 thousand".
        from_scale: The scale the value is written in.
        to_scale: The scale the question asks for.
    """                                                         # ← D
    if not math.isfinite(value):                                # ← E
        raise ToolError("value must be a finite number")
    return format_number(value * _FACTOR[from_scale] / _FACTOR[to_scale])     # ← F
```

逐处解释：

- **A. 用 `Literal` 限定取值。** 单位只有 4 种，写成 `Literal` 后，说明书里是 `enum`，模型只能从中选；传了 `"thousand"`（少了 s）会被 pydantic 拦下，错误信息里还列出了允许的值，模型一看就知道怎么改。**能用 Literal 就别用自由字符串。**
- **B. `@tool`**：只加这一行，第 ②③ 层就自动完成了。
- **C. 每个参数都要有类型注解**；函数名就是工具名（要有意义，只能用字母、数字、下划线、横线）。
- **D. docstring 写三件事**：它做什么；**什么时候用**（"when the excerpt states numbers in one scale ... but the question asks for another"）；**什么时候别用**（"Do not use it for percentages"）。参数描述里给一个具体例子（`5829 for "$5,829 thousand"`）：模型会照着例子的格式填。
- **E. 可以预见的错误，抛 `ToolError`，信息写给模型看。** JSON 标准里没有 NaN，但 Python 的 `json.loads` 接受 `NaN`（L02 讲过的坑），pydantic 的 float 也放行，所以函数自己检查。
- **F. 返回短字符串。** 返回值会作为 tool 消息发回给模型，下一轮要算输入 token。只返回需要的东西。

### 2.5 第 4 步：写测试

在 [tests/test_tools.py](../tests/test_tools.py) 里加三个测试（完整代码见文件末尾）：

```python
def test_convert_units_schema_uses_enum() -> None:
    params = AVAILABLE_TOOLS["convert_units"].schema()["function"]["parameters"]
    assert params["required"] == ["value", "from_scale", "to_scale"]
    assert params["properties"]["value"]["type"] == "number"
    scales = ["units", "thousands", "millions", "billions"]
    assert params["properties"]["from_scale"]["enum"] == scales


@pytest.mark.parametrize(
    ("arguments", "ok", "text"),
    [
        ('{"value": 5829, "from_scale": "thousands", "to_scale": "millions"}', True, "5.829"),
        ('{"value": 8.7, "from_scale": "billions", "to_scale": "millions"}', True, "8700"),
        ('{"value": 1, "from_scale": "thousand", "to_scale": "millions"}', False, "'thousands'"),
        ('{"value": NaN, "from_scale": "units", "to_scale": "units"}', False, "finite"),
        # ……
    ],
)
def test_convert_units(arguments: str, ok: bool, text: str) -> None:
    step = build_registry(["convert_units"]).execute(ToolCall("c", "convert_units", arguments))
    assert step.ok is ok and text in step.result
```

测试写的是**模型可能传来的参数字符串**，走的是和真实运行完全一样的路径（`build_registry` → `execute` → `Tool.run`）。正常情况、边界情况、错误情况都要有。

```powershell
python -m pytest tests/test_tools.py -q
```

### 2.6 第 5 步：在配置里启用

复制一份配置，比如 `configs/systems/v0.4-units.yaml`，只改两处：

```yaml

  enabled: [calculate, convert_units]
```

### 2.7 第 6 步：真实跑一次

演示脚本第 4 步给模型同时提供两个工具，问："表格以千为单位，2018→2019 收入增加了多少百万？"真实输出（两次运行结果相同）：

```
第 1 轮：一次请求了 2 个调用
    calculate({"expression": "5829 - 5735"}) → 94
    convert_units({"value": 94, "from_scale": "thousands", "to_scale": "millions"}) → 0.094
第 2 轮：不再调用工具，给出最终回答：Net revenue increased by 0.094 million from 2018 to 2019.
```

两点值得注意：

1. **模型选对了工具**：减法用计算器，换算用 `convert_units`，参数也填对了。说明书写清楚的效果。
2. **但它把两个有依赖的调用放在了同一轮。** `convert_units` 需要的 94 是 `calculate` 的结果，可两个调用是同时发出的：模型没等计算器返回，就自己心算出 94 填了进去。这次心算碰巧对了，但它说明：**给了工具，模型也不一定按你设想的顺序用。** 如果想强制"先算再换算"，可以在 prompt 里写明"dependent steps must wait for the previous result"，或者干脆只用计算器一步写完 `(5829 - 5735) / 1000`。到底哪种更好，还是要评测。

### 2.8 第 7 步：用评测决定要不要留下

```powershell
finagent eval --config configs/systems/v0.4-units.yaml --set finqa --split dev
finagent compare runs/eval/<v0.4 的目录> runs/eval/<v0.4-units 的目录>
```

看四样东西：

1. **准确率**有没有显著提高（记得 L04 的教训：重复跑一次）；
2. **`scale_error` 有没有变少**（报告的"错误类型"一节），这是这个工具要解决的问题；
3. **`convert_units` 的使用率**：`results.jsonl` 里每题的 `tool_calls` 字段记着调用了哪些工具；
4. **成本和延迟**：多一个工具，每次请求的说明书就多约 200 个 token（`convert_units` 的说明书约 900 个字符），调用轮数也可能增加。

如果准确率没变、`scale_error` 也没变少，这个工具就不值得留下：它只会让说明书更长、让模型多一个选择。**工具越多不一定越好。**

## 3. 参数类型速查表

实际运行 `@tool` 得到的结果：

| Python 类型注解 | 说明书里的 JSON Schema | 模型传来的 | 注意 |
|---|---|---|---|
| `str` | `"type": "string"` | `"abc"` | 传数字 `5` 会被拒绝（pydantic 不会把数字转成字符串） |
| `float` | `"type": "number"` | `5829`、`5.829` | 字符串 `"5829"` 会被转成数字（宽松模式）；`NaN` 会被放行，要自己检查 |
| `int` | `"type": "integer"` | `3` | `3.5` 会被拒绝 |
| `bool` | `"type": "boolean"` | `true` / `false` | |
| `Literal["a", "b"]` | `"type": "string", "enum": ["a", "b"]` | `"a"` | **取值有限时首选**，传错会列出允许的值 |
| `list[float]` | `"type": "array", "items": {"type": "number"}` | `[1, 2, 3]` | 空列表 `[]` 也能通过校验，函数要自己处理 |
| `datetime.date` | `"type": "string", "format": "date"` | `"2024-01-31"` | pydantic 会解析成 date 对象；`"2024-13-01"` 会被拒绝 |
| `x: int = 2`（有默认值） | 不在 `required` 里，带 `"default": 2` | 可以不传 | |

返回值：`str` 原样返回；其他类型（数字、dict、list）会被 `json.dumps` 成字符串。例如返回 `{"days": 30}`，模型看到的是 `{"days": 30}`。

**尽量用简单类型。** 嵌套的对象、自定义类都能用，但说明书会变长、变复杂，模型更容易填错。

## 4. 写好一个工具的 8 条规则

| # | 规则 | ❌ 反例 | ✅ 正例 |
|---|---|---|---|
| 1 | 名字是动词短语，一看就知道做什么 | `tool1`、`units` | `convert_units`、`calculate` |
| 2 | 描述写清"做什么、何时用、何时别用" | `"Converts units."` | 见 `convert_units` 的 docstring |
| 3 | 参数描述里给例子 | `"The value."` | `"for example 5829 for \"$5,829 thousand\""` |
| 4 | 取值有限的参数用 `Literal` | `scale: str` | `scale: Literal["thousands", "millions"]` |
| 5 | 可预见的错误抛 `ToolError`，说清怎么改 | `raise ValueError("bad")` | `raise ToolError("write numbers without thousands separators: 5829, not 5,829")` |
| 6 | 返回值短，只返回需要的 | 返回整张表 | 返回一个数 |
| 7 | 只读工具可以随便调；**有副作用的**（发邮件、写数据库、下单）要加确认 | 模型直接调用 `send_email` | 先返回草稿，由人确认后再执行 |
| 8 | 安全：**永远不信任模型传来的参数** | `eval(expression)`、`open(path)`、拼 SQL | AST 白名单；路径限制在固定目录；参数化查询 |

关于第 5 条，看一个反例。假设写了一个求平均的工具 `average(values: list[float])`，模型传来空列表时，函数里的 `sum(values) / len(values)` 会抛 `ZeroDivisionError`，模型收到的是 `Error: ZeroDivisionError: division by zero`。它能看懂"除以零"，却不知道是**自己传了空列表**。正确做法是先检查，再抛 `ToolError("values must contain at least one number")`。

## 5. 常见错误

| 错误 | 现象 | 解决 |
|---|---|---|
| 忘了写 docstring | `tool()` 报错："缺少 docstring" | 写上，至少一句描述 |
| 某个参数没写类型注解 | `tool()` 报错："参数 x 缺少类型注解" | 每个参数都写类型 |
| Args 段缩进不对 | 参数描述是空的（说明书里没有 description） | 参数行缩进 4 格，续行缩进 8 格（Google 风格） |
| 写了工具但没注册 | 配置里启用时报"未知的工具" | 在 `AVAILABLE_TOOLS` 里加上 |
| 注册了但没在配置里启用 | 模型从来不调用它（说明书根本没发过去） | 配置的 `tools.enabled` 里写上名字 |
| 启用了但模型不用 | 报告里"用了工具的题"很低 | system prompt 里明确要求；检查工具循环是否开了 JSON mode |
| 两个工具功能重叠 | 模型随机选一个，行为不稳定 | 合并，或者在描述里写清各自的适用场景 |
| 返回一大段文字 | 每轮输入 token 暴涨，花费和延迟上升 | 只返回需要的部分；L07 会讲怎么截断长结果 |
| 工具里 `print` 调试信息 | 模型看不到（只有返回值会回传），而且弄乱终端输出 | 用返回值或日志 |

## 6. 更复杂的工具（后面的课会遇到）

- **需要外部数据的工具**（L07 的 `search_filings`）：模型只传"查什么"（公司、年份、关键词），函数内部去查 L05 建好的索引。索引不能每次调用都重新加载，所以这类工具会写成一个类的方法，或者用闭包持有索引。
- **有副作用的工具**：发消息、写文件、调用付费 API。要加确认环节，还要考虑模型被 prompt injection 诱导去调用它（L07）。
- **让别的程序也能用你的工具**：选修 S2 会把工具包装成 **MCP server**，Claude Code、Claude Desktop 可以直接调用。说明书的格式几乎一样，这就是为什么先把本课的机制弄懂。
