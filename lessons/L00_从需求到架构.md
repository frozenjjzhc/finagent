## 1. 为什么不直接写代码？

AI 项目（包括很多简历项目）常见的三种失败方式：

| 失败方式 | 表现 | 面试时的后果 |
|---|---|---|
| **没定义"好"** | 做完一个 demo，但说不出它多好，也不知道改动有没有用 | "你怎么评估的？"答不上来 |
| **技术先行** | "我想做个 LoRA 项目"，然后找题目 | "这个问题为什么不用 RAG？"答不上来 |
| **只有 demo** | 精心挑的 3 个例子能跑 | "失败的 case 长什么样？"答不上来 |

面试里 **"Design an LLM-powered system for X"** 这类题，标准回答顺序是：

```
澄清需求 → 定义指标 → 最简 baseline → 按指标迭代 → 部署与监控
```

这节课练的就是前两步，后面 16 课依次完成后三步。

## 2. Step 1 · 选题：好的学习项目领域有 4 个标准

| 标准 | 为什么重要 | 财报问答满足吗？ |
|---|---|---|
| **数据免费可得** | 不被数据卡住 | ✅ SEC EDGAR 完全公开 |
| **答案可自动验证** | eval 又便宜又可靠；也是 L14 强化学习（可验证奖励）的前提 | ✅ 数值题可以精确判分 |
| **难度可分层** | 每一层难度对应一种技术，项目才能"慢慢进化" | ✅ 事实查找 → 计算 → 多跳对比 → 无答案拒答 |
| **有公开 benchmark** | 你的数字能和论文对比，面试官更容易相信 | ✅ FinQA、FinanceBench |

另外两个加分项：真实痛点（10-K 又长、表格又多、要算数），以及和你的量化方向、`ai-equity-research` 一脉相承。

**反例**，看看为什么不选它们：
- "做一个聊天机器人"：答案无法验证，eval 做不起来。
- "情感分类"：不需要 RAG、不需要工具，大部分知识点用不上。
- "代码助手"：可以做，但 eval（跑测试）的基础设施更重，而且和你的求职方向重合度不如金融。

> 💡 **难度分层**是"慢慢进化"能成立的关键。看这张对应表：
> ```
> 题目类型                     第一次被解决的版本    靠的技术
> 单跳事实（"FY24 收入？"）     v0.5                 RAG
> 需要计算（"同比增长？"）      v0.4                 Tools
> 多跳对比（"A vs B 两年"）     v0.7                 Agent
> 无答案（资料里没有）          v0.2 → v0.13         Prompt → DPO
> 同样的事，便宜地做            v0.8 → v0.14         本地模型 + 微调
> ```

## 3. Step 2 · 从问题到需求

打开 `docs/PRD.md` 对照着读。

### 3.1 用户故事：As a ___, I want ___, so that ___

用户故事逼你回答两个问题：**谁**在用，**为什么**用。后面的"验收标准"让需求**可以测试**。

对比一下：
- ❌ "系统要准确。"（多准算准？怎么测？）
- ✅ "数值与标准答案相对误差 < 1%。"（可以直接写成 eval 里的一行代码）

好的需求可以直接翻译成测试。你会在 L03 看到 PRD 里的验收标准一条条变成 `eval/metrics.py` 里的函数。

### 3.2 功能需求 vs 非功能需求

- **FR（Functional）**：系统**做什么**。例："回答附带引用"。
- **NFR（Non-functional）**：系统**做得多好**、**在什么约束下**做。例：准确率、成本、延迟、显存、隐私、可复现。

**本课最重要的洞察之一：架构往往是由 NFR 决定的，而不是 FR。**
只看功能需求，一个 LLM API 调用 + RAG 就够了。真正塑造 FinAgent 架构的是这几条 NFR：

| NFR | 它逼出来的设计 |
|---|---|
| 8GB 显存 | 只能 LoRA / QLoRA，模型 ≤ 4B（L09、L12） |
| 边际成本 ≈ 0 + 隐私 | 必须有本地模型，于是需要蒸馏（L08–L14） |
| 后端可切换 | `LLMClient` 统一接口（ADR-1） |
| 可复现 | config 驱动 + 不可变的 eval run 目录（ADR-2、ADR-3） |

### 3.3 非目标（Non-goals）

个人项目最常见的死法是**范围蔓延**：做着做着想加 10-Q、加电话会、加中文、加前端……最后什么都没做完。
非目标就是提前写下"**明确不做**"的清单。它还有一个副作用：`"不做投资建议"` 本身变成了一条需求，也就是 L16 的 guardrail。

### 3.4 指标先于实现，但具体数字后定

PRD 里写的是"准确率 ≥ __%"，数字**故意空着**。

- **现在就定的**：**怎么量**（指标定义：数值题用相对误差 < 1% 的 exact match，文本题用 LLM judge……）
- **L03 再定的**：**量到多少**（拿到 baseline 之后才知道空间在哪里）

没有 baseline 就定目标，要么定太低（没意义），要么定太高（做不到，只能改目标，等于没定）。

## 4. Step 3 · 从需求到技术 ★ 本课最重要的一节

### 4.1 痛点 → 根因 → 技术

这张表就是整个课程的"目录"。每一行的格式都是：遇到了什么问题 → 为什么会这样 → 用什么技术解决。

| 痛点（用户看到的） | 根因（技术上的） | 技术 | 课次 |
|---|---|---|---|
| 模型不知道 FY2025 的财报 | 知识截止；私有、长尾知识不在权重里 | **RAG** | L05–06 |
| 增长率算错 | tokenization 把数字切碎；LLM 不是计算器 | **Tool use** | L04 |
| 输出没法用程序解析 | 自由文本、格式不稳定 | **Prompt + 结构化输出** | L02 |
| 不知道改动有没有用 | 没有度量 | **Eval** | L03 |
| 对比类问题答不了 | 一次调用无法规划多步 | **Agent** | L07 |
| 贵、慢、数据要外发 | 依赖大模型 API | **本地小模型 + 蒸馏** | L08, L10 |
| 小模型不会用工具 | 能力不足、格式不熟 | **SFT + LoRA** | L09, L11 |
| 8GB 放不下 4B 模型 | 显存 | **QLoRA** | L12 |
| 小模型爱编数字 | SFT 只学了正例，没见过"错是什么样" | **DPO / RL** | L13–14 |
| 要给别人用 | 没有服务 | **Serving + Guardrails** | L15–16 |

### 4.2 技术阶梯：从便宜到昂贵

```
 成本/复杂度
   ^
   |  RL (GRPO)         结果能自动验证时，直接优化结果
   |  偏好对齐 (DPO)    SFT 之后仍然"格式对了但会犯错"
   |  微调 (SFT/LoRA)   要改变行为/格式/风格，或者把大模型能力压进小模型
   |  Agent             需要多步规划
   |  Tools             需要精确计算，或需要访问外部系统
   |  RAG               缺知识（新的、私有的、长尾的）
   |  Prompt            先把话说清楚
   +------------------------------------------------------------>
```

**原则：从下往上逐级尝试。每往上走一级，都要有 eval 证明下面那一级不够用。**
这正是本课程的顺序，也是工业界的顺序。

### 4.3 经典面试题：RAG vs Fine-tuning

**一句话：RAG 补"知识"，微调改"行为"。**

| 维度 | RAG | Fine-tuning |
|---|---|---|
| 解决什么 | 模型**不知道的事实** | 模型**不会的做法**（格式、风格、工具调用习惯、领域推理模式） |
| 知识更新 | 改文档即可，立即生效 | 要重新训练 |
| 可溯源 | 天然能给出处 | 很难 |
| 对幻觉 | 有依据，降低幻觉 | 可能把错误"训进去" |
| 成本结构 | 每次查询多花上下文 token | 一次性训练成本；之后推理可以用更小的模型 |
| 数据需求 | 文档本身就够 | 需要成形的训练样本（几百到几万条） |

**常见误区**："用微调把公司财报灌进模型。"
这通常是错的。微调记事实的效率很低（同一个事实要以多种说法重复很多次），知识更新要重训，没法溯源，还容易让模型学会"很自信地说"却记混数字。财报里全是数字，更是如此。

**高分回答**：两者**互补**，不是二选一。FinAgent 两个都用，而且分工明确：
- RAG 负责**提供知识**（从 10-K 里找到数字）；
- SFT 负责**教小模型行为**（怎么调用检索、怎么用计算器、怎么按格式回答、什么时候拒答）。

### 4.4 为什么要"蒸馏到小模型"？给后半程一个真实的理由

说实话：很多真实产品做到 RAG + Tools + Agent（也就是 v0.7）就够了。我们继续往下走，是因为 NFR 里有真实的动机：

1. **隐私与合规**：金融机构常常不允许把数据发给外部 API，更别说发到境外。这是最硬的一条。
2. **可控**：权重在自己手里，不受 API 改版、下线、涨价的影响。DeepSeek 的模型名就已经变过好几次（`deepseek-chat` 已经不在当前文档里，`deepseek-v4-flash` 也已退役、改叫 `deepseek-flash`），依赖外部 API 的系统都得跟着改。
3. **延迟**：本地推理没有网络往返。
4. **成本**：DeepSeek 已经很便宜，所以这条理由**变弱了**。不过流量大了仍然是钱，专门微调过的小模型还能更便宜。

换成 DeepSeek 之后成本理由变弱，这反而是好事，它逼你想清楚真正的动机。面试时如果你说"为了省钱所以蒸馏小模型"，面试官一句"DeepSeek 已经很便宜了"就能问住你；"合规 + 可控 + 延迟"才站得住。

面试时这样讲，LoRA、SFT、DPO 就是"为了解决 X 而用的"，而不是"为了用而用"。
**注意，这也意味着**：如果 L08 发现 1.7B 裸跑已经足够好，那后面的微调就不需要了。当然实际上不会足够好，L08 你会亲眼看到差距有多大。

## 5. Step 4 · 从技术到架构

打开 `docs/ARCHITECTURE.md` 对照着读。

### 5.1 找"变化轴"：未来什么会变，就把它藏到接口后面

做架构设计时最有用的一个问题是：**在这个项目的生命周期里，什么东西会变？**

| 会变的东西 | 什么时候变 | 架构对策 |
|---|---|---|
| 模型后端：DeepSeek API → 本地 Qwen（进程内）→ 本地推理服务 | L08、L15 | `LLMClient` 接口 + 统一采用 OpenAI 消息格式 |
| 检索策略：dense → hybrid → rerank | L06 | Retriever 接口 + config 开关 |
| Prompt 内容 | 几乎每课 | `prompts/` 目录，文件名带版本号 |
| 工具集合 | L04、L07 | 工具注册表（装饰器注册） |
| 编排方式：单次调用 → tool loop → ReAct | L02、L04、L07 | pipeline 可替换 |

用最重要的第一行举例，看"接口"具体长什么样（**只是示意，真代码在 L01 写**）：

```python
# src/finagent/llm/base.py（L01 实现，这里是草图）
from typing import Protocol

class LLMClient(Protocol):
    def chat(self, messages: list[Message], tools: list[ToolSpec] | None = None) -> LLMResponse:
        """发送一轮对话，返回统一格式的响应（文本 / 工具调用 / token 用量）。"""
        ...
```

```yaml
# configs/systems/v0.7.yaml：老师，DeepSeek API
llm: { backend: openai_compat, base_url: "https://api.deepseek.com", model: deepseek-flash }

# configs/systems/v0.8.yaml：学生，进程内加载权重（和 v0.7 相比只改了这一行）
llm: { backend: local_hf, model: Qwen/Qwen3-1.7B }

# configs/systems/v0.15.yaml：学生，走本地推理服务（和 v0.7 是同一个类，只换了地址）
llm: { backend: openai_compat, base_url: "http://localhost:8000/v1", model: finagent-student }
```

**回报**：从 v0.7 到 v0.8，eval、agent、RAG、工具的代码一行都不用动，只改一行 config。

到了 v0.15 更省事：DeepSeek 和本地 vLLM 说的是同一种 API 格式（OpenAI 兼容），连 adapter 都不用新写。**选一个事实标准当内部格式**，本身就是一个架构决策（见 ADR-1）。
这种"把会变的东西藏在接口后面"的技巧，设计模式里叫 **Adapter**，更一般的原则叫 **依赖倒置**：上层依赖抽象，不依赖具体实现。

### 5.2 找"横切关注点"

有些东西**每一层都需要**：eval、tracing（记录 token / 成本 / 延迟）、config。
它们不属于任何一层，所以放在底部的公共模块，所有层共用，不在各处重复实现。

### 5.3 分层与依赖方向

规则只有一条：**依赖只能向下**。下层不知道上层的存在。

- `rag/retriever.py` 不 import `agent/`；
- `llm/` 不知道谁在调用它。

好处：每一层可以单独测试；替换下层（比如换向量库）不影响上层。

### 5.4 演进式架构：蓝图画全，实现只做当下需要的

ARCHITECTURE.md 画的是 v1.0 的完整蓝图，但**本课只建了骨架**，`src/finagent/` 里只有一个 `__init__.py`。

为什么不一次把所有目录和接口建好？
1. **需求会变**，提前写的抽象多半是错的（这个原则叫 YAGNI：You Aren't Gonna Need It）。
2. 空目录和空接口是负担：你得维护它们，却不知道它们该长什么样。
3. **学习上**，每个模块都应该在"你需要它"的那一刻出现，这样你才知道它为什么存在。

### 5.5 ADR：把"为什么"写下来

ADR（Architecture Decision Record）就是一条条"**背景 → 决定 → 代价**"。
写给两个人看：三个月后忘了为什么这么做的你，和问"为什么不用 LangChain"的面试官。
看 ARCHITECTURE.md 第 3 节的 8 条 ADR。**注意每条都写了代价**：没有代价的决策，说明你还没想清楚。

## 6. Step 5 · 工程骨架

### 6.1 现在已经有的文件

```
finagent/
|-- README.md             项目门面
|-- ROADMAP.md            17 课路线 + 进度勾选
|-- SCOREBOARD.md         评测记分板（L03 开始填）
|-- pyproject.toml        项目元数据 + 依赖
|-- .env.example          密钥模板（可提交）
|-- .gitignore
|-- docs/                 PRD.md  ARCHITECTURE.md
|-- lessons/              L00_从需求到架构.md（本文）
|-- scripts/check_env.py  环境自检
'-- src/finagent/__init__.py
```

### 6.2 为什么用 src layout（代码放在 `src/finagent/` 而不是 `finagent/`）

如果包直接放在项目根目录，你在根目录运行 Python 时，`import finagent` 会**直接导入本地文件夹**，哪怕这个包根本没安装成功。结果就是：本地测试全过，别人 `pip install` 之后缺文件、报错。

src layout 让你**必须先安装**（`pip install -e .`）才能 import，所以你测试的永远是"安装后的包"。
`-e`（editable，可编辑安装）的意思是：安装的是一个指向源码的链接，改了代码立即生效，不用重装。

### 6.3 `pyproject.toml` 逐段看

打开文件对照：

- **`[build-system]`**：告诉 pip 用什么工具构建这个包（setuptools）。
- **`[project].dependencies`**：**只列 L01–L04 需要的核心依赖**。依赖越少，环境越不容易出问题。
- **`[project.optional-dependencies]`**（extras）：后续阶段的依赖按组放，到了那一课再装：
  ```
  pip install -e ".[rag]"      # L05
  pip install -e ".[train]"    # L08
  ```
  （PowerShell 里引号必须加，否则 `[` 会被当成特殊字符。）
- **`[project.scripts]`**：暂时注释掉，L01 写好 `cli.py` 之后打开，你就能在终端直接敲 `finagent ask ...`。
- **为什么现在不锁死版本号**：学习项目需要灵活性。到了里程碑（v0.3、v0.7……）我们会用 `pip freeze > requirements.lock` 记下确切版本，在可复现和灵活之间取个平衡。
- **为什么 torch 不在依赖里**：你在 nanolm 里踩过这个坑。Windows 上 `pip install torch` 默认装的是 **CPU 版**，CUDA 版必须从 PyTorch 官方源装（见 7.3 节）。

### 6.4 密钥管理

- 真实密钥放在 `.env`（已被 `.gitignore` 忽略），代码通过 `python-dotenv` 读取。
- `.env.example` 只放占位符，**可以提交**，告诉别人需要哪些变量。
- **三不**：不写进代码、不打印出来、不放进 URL。
- 如果不小心提交了：**立刻去控制台吊销（revoke）这个 key**。只从 git 里删掉是不够的，git 历史会永久保留它。

### 6.5 `.gitignore` 里值得注意的一行

```
/data/
```

开头的 `/` 表示"只匹配项目根目录下的 data"。如果写成 `data/`，那么 L05 要建的 `src/finagent/data/`（数据加载代码）也会被忽略，代码就提交不上去了。一个斜杠的差别。

## 7. 动手：搭环境（约 1 小时）

### 7.1 创建独立的 conda 环境

为什么不用 base 环境？后面要装 transformers / trl / peft，这些库版本迭代很快，装进 base 可能会弄坏 nanolm 或其他项目。**一个项目一个环境。**

```powershell
conda create -n finagent python=3.12 -y
conda activate finagent
cd D:\claude\best\finagent
pip install -e ".[dev]"
python scripts/check_env.py
```

这时应该只有 `DEEPSEEK_API_KEY` 和 `.env` 两项是 `[MISSING]`。

> ⚠️ **Windows PowerShell 的常见坑**：`conda activate finagent` 之后，提示符前面必须出现 `(finagent)` 才算激活成功。
> 如果命令没报错、提示符却没变，说明 PowerShell 还没做 conda 初始化。这时 `conda` 调用的是 `conda.bat`，激活只发生在一个 cmd 子进程里，子进程退出就没了（环境变量只能从父进程传给子进程，不能反过来）。
> 解决：运行一次 `conda init powershell`，然后**重开终端**，提示符前面会出现 `(base)`。

### 7.2 API key

1. 打开 DeepSeek 开放平台（platform.deepseek.com），创建一个 API key。
2. DeepSeek 是**预充值**扣费，余额本身就是花费上限，程序就算死循环也烧不穿。先充 $10 左右，够用很久（价格估算见 PRD 第 5 节）。

## 10. 参考答案

**1.** 先**澄清需求**，别急着画 vector DB：用户是谁？问哪类问题（事实 / 计算 / 多跳）？数据范围（多少家公司、几年）？质量要求（准确率、必须带出处、不能编）？约束（延迟、成本、隐私、部署环境）？然后**定义指标**（数值 exact match、引用正确率、拒答率），说明会先做一个**最简 baseline**（prompt + RAG），再**按 eval 结果**逐步加 tools、rerank、agent。这个顺序本身就是在加分。

**2.** RAG 补知识，微调改行为。缺事实、事实会更新、需要溯源的时候用 RAG；需要改变格式、风格、工具使用习惯，或者要把大模型能力压进小模型的时候用微调。可以同时用：FinAgent 就是 RAG 提供知识，SFT 教小模型怎么用检索和工具。

**3.** 微调记事实效率低（需要大量重复和改写）；知识更新要重训；无法溯源；容易增加幻觉，模型学会了自信的语气，数字却记混。财报里数字密集，这些问题更严重。

**4.** FR 是"做什么"，NFR 是"做得多好、在什么约束下做"。例子：8GB 显存 → 只能用 LoRA/QLoRA、模型 ≤ 4B；隐私 + 成本 → 需要本地模型，于是需要蒸馏；可复现 → config 驱动 + 不可变的 run 目录。

**5.** 定义中立接口（`LLMClient`），业务代码只依赖接口；每个后端写一个 adapter，负责消息和工具调用格式的转换（内部直接采用 OpenAI 兼容格式这种事实标准，很多后端连 adapter 都省了）；用 config 选择后端；切换前后用**同一套 eval** 验证质量有没有变化。

**6.** 没有 baseline 的目标是拍脑袋：可能太低（没意义）或太高（做不到）。先测出 closed-book 和简单 RAG 的分数，才知道提升空间在哪、多大的提升算显著。

**7.** 防止在没安装的情况下误导入本地源码，保证测试的是"安装后的包"；配合 `pip install -e .`，改代码立即生效。
