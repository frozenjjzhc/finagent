# FinAgent · 产品需求文档（PRD）

> 版本 0.2 · 2026-09-25（老师模型改为 DeepSeek）· 作者：Hanchen Zou
> 这是一份**活文档**：每完成一个阶段，回来更新"状态"列和第 4 节的目标数字。

---

## 1. 背景与问题

美股上市公司每年要交一份 10-K 年报，动辄 100～300 页，关键数字分散在正文、表格和附注里。分析师和投资者常问的问题看起来简单，比如：

- "Apple FY2024 服务业务收入同比增长多少？"
- "NVIDIA 过去三年的毛利率趋势？"
- "对比 Microsoft 和 Alphabet 最近一年的研发费用占收入比。"

回答它们需要三步：**找到**正确的段落或表格 → **读对**数字（单位、财年、口径）→ **算对**（增长率、比率）。手工做很慢；直接问通用聊天机器人，它会自信地给出一个**编出来的**数字。

## 2. 用户与用户故事

**目标用户**：研究美股的个人投资者或初级分析师。

| # | 用户故事 | 验收标准 |
|---|---|---|
| U1 | 作为用户，我问一个关于某公司 10-K 的事实性问题，想得到**准确答案和出处**，以便核实 | 答案附带来源（公司、财年、章节/页码或 chunk id） |
| U2 | 我问一个需要计算的问题（增长率、比率、差值），想得到**正确数值和计算过程** | 数值与标准答案相对误差 < 1%；展示算式 |
| U3 | 我问一个跨公司或跨年份的对比问题 | 能自动拆成子问题，分别检索再汇总 |
| U4 | 当资料里没有答案时，我希望它**明确说不知道**，而不是编 | 无答案题的正确拒答率达标（目标见第 4 节） |
| U5 | 我问"该买哪只股票"，它应当拒绝给投资建议 | 越界请求 100% 拒答并说明原因 |
| U6 | 作为开发者，我想通过 API 调用它，拿到结构化 JSON，也能流式返回 | 提供 JSON schema 与 SSE 接口 |
| U7 | 作为开发者，我希望它能在本地离线运行，不把数据发给第三方，且边际成本接近 0 | 学生模型在 8GB 显卡上完整跑通 eval |

## 7. 非目标（明确不做）

- 投资建议、股价预测、实时行情、交易执行
- 10-Q / 8-K / 电话会纪要（架构留好扩展口，v1.0 之后可加）
- 多语言问答（先只做英文财报；你用中文提问可以作为加分项）
- 从头预训练大模型（nanolm 已覆盖原理）
- 多卡 / 分布式训练

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| API 成本超预算 | 日常只跑 dev 子集；全量 test 只在里程碑跑；批量任务放在非高峰时段；利用上下文缓存；SFT 数据优先用 FinQA 程序化合成 |
| 老师 API 变化（DeepSeek 更新快，模型名已经变过几次） | 模型名和 base_url 全部写进 config；每个 eval run 记录模型名与日期；里程碑时重跑 baseline |
| 8GB 显存不够 | 0.6B 迭代 → 1.7B LoRA → 4B QLoRA；短序列；gradient checkpointing |
| 财报表格解析困难 | FinQA 自带已解析的表格；10-K 表格转 markdown；表格和正文分开 chunk |
| Windows 兼容问题（vLLM、flash-attn） | 用 SDPA 注意力；llama.cpp / Ollama；vLLM 走 WSL2 |
| eval 集太小导致结论不可靠 | bootstrap 置信区间；只把显著差异当结论 |
| 进度拖延 | L07 是第一个里程碑，先保证它按时完成（可写进简历） |
